Итоговая сводка проекта **protocell-genesis**, ветка `stage-a-atoms`, состояние на **2026-08-20**.
Написана для человека, которого здесь не было: читать её достаточно, чтобы понять результат, его

## 1. Что проверяли

Один вопрос: **соберётся ли из огрублённого «бульона» мономеров самособранная ЗАМКНУТАЯ везикула** —
объект, у которого есть внутренность, недоступная снаружи, и стенка-бислой вокруг неё.

Правила проекта, которые определяли, что считается ответом:

- **Ворота — это утверждение с числом модели, литературным интервалом, вердиктом и рангом довода**
  (спецификация `docs/superpowers/specs/2026-08-15-protocell-genesis-design.md`, раздел 8). Ворота
  публикуются как **пройдены / провалены / недоказаны** и **никогда не расширяются**, чтобы пройти.
- **Ранги довода** (спецификация, раздел 3): **A** — измерено (ссылка, условия, погрешность);
  **B** — посчитано; **C** — ограничено термодинамикой / отношения взяты из независимого источника;
  **D** — оценка, и **ворота, опирающиеся только на D, выходят недоказанными по определению**.
- В `engine/` не должно быть ни одной вписанной руками химической константы: движок читает `data/`.
- Гидрофобность обязана быть **эмерджентной** (из вытеснения водой), а не заданной прямым
  притяжением хвостов.

### 3.1 Два ворота, которые есть новый результат этой кампании

Бислой **в жидкой явной воде 0.8 σ⁻³** держит и площадь, и толщину: **1.1597 σ² / 4.5311 σ**, ядро
сухое (55 водяных бидов из 4500 внутри), доля закопанных голов **0.1608**, кластер 1.0000, площадь
**осела** (дрейф ln A −3.42e−6 за отсчёт, t = −0.73 на 450 отсчётах). Площадь здесь **измерена** ходом
по площади при нулевом натяжении, а не задана построением.

Это важно потому, что до задачи `hydrophobic-asymmetry` (2026-08-19) та же заплатка в воде давала
**12.2–12.4 σ** при коридоре 4–6 и площадь была допущением 1.3 σ²
(`broth-composition-report.md` §4). Механизм провала нашла задача `water-calibration`: не проникновение
воды в ядро (ядро было сухим) и не отсутствие ядра, а **закапывание голов** — 40–49 % головных бидов
сидели внутри гидрофобной зоны, потому что удаление старого члена «хвост–хвост» оставило листок вообще
без латеральной когезии. Исправление — не подгонка, а **отношения глубин пар из MARTINI 2.1**
(`martini_v2.1.itp`, `[nonbond_params]`, ε = C6²/(4·C12)): вода–вода 5.0, вода–голова 4.0,
хвост–хвост 3.5 (эталон, множитель ровно 1.0), вода–хвост 2.0 кДж/моль. Обменная (флори-хаггинсовская)
энергия при этом положительна: 5.0 + 3.5 − 2·2.0 = **+4.5 кДж/моль**, то есть смешение по-прежнему
невыгодно и гидрофобность осталась эмерджентной. Абсолютная глубина не перефитировалась: хвост–хвост
бит-в-бит равен ранг-A ε из `data/params.json`.

Ранг **C**, а не A: коридор литературный (ранг A), но число получено в среде, чьи отношения глубин
взяты из чужого силового поля и на этом дереве не калиброваны, а `epsilonScale = 1.0` несёт ранг D.

### 3.2 Статистика длин цепей

На последнем снимке кампании (шаг 176 400): событийное **α_ev = cc_bond/(cc_bond+co_bond) = 0.7513**,
ASF-среднее `1/(1−α_ev)` = **4.020** против измеренного среднего на хвост **3.490** (расхождение
**15.2 %**). Независимая оценка того же α из самой гистограммы длин — **α_rec = 0.7732** при r² = 0.928
лог-линейной подгонки, то есть два независимых пути к одному параметру сходятся с точностью **2.9 %**,
и форма распределения геометрическая, что и есть подпись Андерсона–Шульца–Флори
(van der Laan & Beenackers, *Catal. Rev. Sci. Eng.* **41** (1999) 255–318).

Ворота всё равно **недоказаны**, и причина названа прямо: спецификация формулирует критерий этих ворот
как «расхождение гистограмм», не давая числового коридора, а независимого литературного коридора для α
именно этой системы не существует. Придумать коридор здесь означало бы подогнать ворота под результат.

Длина хвоста **3.490** лежит ВЫШЕ окна 2–3, которое подразумевает наше собственное отображение
«C8 → 2, C12 → 3, C16 → 4» (спецификация, раздел 4). Отображение несёт ранг D и принимается только
через ворота площади и толщины, поэтому эти ворота выходят недоказанными, а не проваленными. Честное
замечание: если бы отображение имело независимый коридор, это было бы **провалом**. И длина хвоста
здесь не одно число, а тренд: **2.845 → 3.490** по ходу одного прогона при неизменном составе.

## 4. Вердикт и механизм

**ЗАМКНУТОЙ ВЕЗИКУЛЫ НЕТ. Ни на одном снимке ни одной кампании.**

Последняя и самая крупная кампания: бокс **54 σ**, **N = 191 778**, жидкая вода
ρ_W = 125 971/157 464 = **0.79999 σ⁻³**, состав O:C = **0.333**, одно событие высушивания,
**176 400 шагов**, из которых 135 000 осевших. Начало — решётка одних мономеров на своём шаге 0,
ничего готового.

Чем это кончилось (`verify/out/gates-campaign-trace.json`, снимки 41 400 … 176 400):

| величина | измерено | нужно | вердикт |
|---|---|---|---|
| подача амфифилов | 2109.2 | ~1004 | **2.10× НАД порогом — снято** |
| размер крупнейшего агрегата | 2087.2 (последние пять в пределах 0.37 %) | ~1004 | **2.08× НАД порогом — снято впервые в проекте** |
| краевая энергия на молекулу | 0.583 kT при N = 2087 | ≲ 1 kT | **снято** |
| **связность: обёртывающих осей** | **3 из 3**, слоёв 19/19 | **0** | **СВЯЗЫВАЮЩЕЕ ОГРАНИЧЕНИЕ** |
| инкапсулированная вода | **0** | ≥ 317.1–320.9 бида | ниже по течению |
| радиальных слоёв голов | **1** | 2 (стенка бислоя) | ниже по течению |
| полость | 50.5 ± 1.6 σ³ | ≥ 370.8656 σ³ | в 7.3 раза меньше |
| плоскостность λ₁/λ₃ | 0.65–0.81 | ≤ 0.35 | в 2.20 раза больше |

**Механизм, одной фразой: при той доле двухвостых голов, при которой бислой становится
предпочтительной формой, концентрация амфифилов, необходимая этой модели для хоть какой-то химии,
ставит систему ВЫШЕ её собственного порога гелеобразования.** Объект, протянутый через периодический
бокс, не имеет ни «внутри», ни «снаружи» — он не может замкнуть ничего, каким бы большим ни был.

Как это измерено, а не выведено. `tests/percolation-check.test.ts` берёт частицы крупнейшего агрегата,
реплицирует их один раз вдоль оси на +L с этой осью, сделанной открытой, соединяет пары по **тому же**
радиусу связности, что и весь проект, и спрашивает: попала ли частица в одну компоненту со своим
собственным образом. Порога здесь не вводится — у конечного объекта таких осей 0 по определению.
Прибор различает: на трёх системах, которые проект называет конечными стержнями (решающий прогон на
шагах 41 400 и 174 400 — крупнейшие 200 и 151 молекул; плечо A на боксе 30 — 154), он даёт **0 осей из
3** и касается 7–13 слоёв из 19. Независимо и без чьего-либо умысла то же самое говорит
`soup/src/water-closure.ts`: он ОТКАЗЫВАЕТСЯ отвечать (центр не надёжен) на 9 из 15 влажных снимков,
потому что протяжённость объекта сравнима с боксом.

Две регулярности этой модели, между которыми ничего не измерено:
**конечные стержни, которые слишком малы** (O:C = 4: крупнейший 151, в 6.0 раза меньше порога, 0
обёртывающих осей) и **одна сетка, которая достаточно велика, но у неё нет внутренности**
(O:C = 0.333: крупнейший 2087, 2.08× над порогом, 3 обёртывающие оси). Плечо O:C = 1.000 — не
середина: оно тоже перколирует (3 оси из 3 на боксе 30).

## 5. Пять настоящих дефектов, найденных по дороге, и какие опубликованные числа они сдвинули

Это не косметика: каждый из пяти делал опубликованное число неверным, и каждый исправлен с
пришпиливающим тестом, который упадёт, если дефект вернётся.

### 5.1 Выбор кончика цепи при нуклеации — `soup/wgsl/bond-adsorption.wgsl`

Нуклеация цепи на катализаторе требовала **замкнутого треугольника**: контакт голого углерода `i` с
`j`, контакт катализатора с `i` И контакт катализатора с `j`. Но `bondFormWalk` к этому моменту уже
установил контакт катализатора именно с `i`, а ветка нуклеации объявляла кончиком `j` и требовала
контакт ДРУГОГО углерода. Диагноз — не рассуждение, а счётчик (`verify/center-nucleation.ts`, чистый
CPU): число подходящих троек падало **393 → 3 → 0** к шагу 120 000 и оставалось нулём до шага 300 000,
при 5125 свободных голых углеродах и 1021 свободном катализаторе. То есть химия останавливалась
не потому, что кончалось сырьё, а потому, что геометрическое условие старта было невыполнимым.
Исправление: кончиком становится тот углерод, контакт которого с катализатором УЖЕ установлен.
**Сдвинутые числа** (бокс 30, сид 20): нуклеаций **117 → 192**, амфифилов **56 → 129**,
непрореагировавшего голого углерода **133 → 33 из 779**.
Отчёт: `catalyst-turnover-and-window-report.md`.

### 5.2 Чекпойнты с нулевым ГПСЧ — `soup/src/checkpoint.ts` / `readBack`

У буферов `bondRngBuf` / `thermoRngBuf` не было флага `COPY_SRC`, поэтому копирование при чтении было
ошибкой валидации, отправка команд — пустышкой, и наружу возвращался **нулями инициализированный
промежуточный буфер**. Все **72 чекпойнта на диске** содержали 100 % нулевых байт ГПСЧ: каждый
возобновлённый прогон в истории проекта получал зерно 0 для ВСЕХ N частиц, то есть одинаковый шум
Ланжевена на каждой частице. Система при этом двигалась жёстко целиком (измеренное MSD 62.32 σ²,
одинаковое для всех семи классов видов), и **относительная** диффузия была уничтожена — поэтому
агрегаты не могли сливаться.
**Сдвинутые числа** (бокс 54, тот же состав/сид/шаги, изменён один параметр): крупнейший агрегат на
шаге 90 000 **268 → 588** (в 2.19 раза), и вместо плато «271, замороженное со шага 135 000 до 315 000»
получился рост 232 → 281 → 333 → 588; замкнутый объём крупнейшего агрегата
**6.25–6.75 → 17.125 σ³** (в 2.74 раза). Отставание по размеру агрегата в опубликованной
последовательности при этом оказалось не «в 3.36 раза», а **в 1.85 раза**.
`readBack` теперь БРОСАЕТ исключение на буфере без `COPY_SRC`, поэтому класс ошибки не может повториться
молча. Отчёты: `loud-failure-and-liquid-water-report.md`, `evaporation-report.md` §7.

### 5.3 Устаревшая F(x) после смены размера бокса — `applyBoxScaleOnce`

Смена бокса (высушивание/регидратация) перестраивала сетку соседей и список Верле — и на этом
останавливалась, поэтому `kick_drift_wrap` брал в качестве F(xₙ) силу, посчитанную ДО
перемасштабирования координат. Пришпилено в обе стороны (`tests/soup-stale-force.test.ts`, чтение сил
без перестройки): с исправлением резидентный буфер согласуется со свежим расчётом до 1.5e−4 при
масштабе силы 513; без исправления он бит-в-бит равен старой силе и **ошибается на 313.7**.
**Сдвинутые числа** (бокс 30, шаг 36 800, n = 3 с каждой стороны): крупнейший агрегат
**249.3 [210, 273] → 109.3 [71, 154]** — сжатие в **2.28 раза** с неперекрывающимися диапазонами,
при том что выход (0.1516 → 0.1525) и число связей (1436 → 1392) не двинулись. То есть честный эффект
циклирования — выход в 1.68–1.80 раза, связи в 1.76–1.93 раза, крупнейший агрегат в 8.1–8.4 раза, а
**не опубликованные 12.5–14.5 раза**. Побочно выяснилось, что страж рампы, срабатывавший 9 раз из 216 у
предшественника, был проявлением этого же дефекта, а не физики: после исправления он срабатывает
**0 раз из 36**. Отчёт: `decisive-run-report.md` §2.3.

### 5.4 Молчаливая расходимость — `soup/wgsl/health.wgsl`

Страж `assertVerletSafety` сравнивал `sqrt(maxDriftSq) > skin/2`, а **любое** сравнение с NaN ложно:
как только позиции становились NaN, дрейф читался как NaN и проверка проходила **навсегда**. То есть
страж работал и был слеп по построению. Добавлено сканирование экспонент IEEE-754 за O(N) на том же
такте и в той же точке синхронизации, **перед** старой проверкой. Стоимость замерена, а не оценена:
**0.212 мс против 331.68 мс на чанк в 1000 шагов = 0.064 %**. На том самом составе предшественника,
который расходился молча (ρ_tot 0.75, бокс 30), он теперь БРОСАЕТ исключение на шаге 1000, называя
**6957 нефинитных компонент из 60 750**. Что это сдвинуло: не число, а класс утверждений — любой
прогон, «успешно» дошедший до конца через NaN, публиковал числа ни о чём, и теперь такое падает
громко. Отчёт: `loud-failure-and-liquid-water-report.md`.

### 5.5 Двойной счёт на границе по z — `engine/src/aggregate.ts`

`buildClusterUnionFind`, через который проходит **каждое определение стадии в этом проекте**, считал

по z, разрезался и считался дважды. Исправление — флаг `periodicZ` со значением по умолчанию `false`,

## 6. Что остаётся недоказанным, спорным или измеренным одним сидом

1. **Кампания — ОДИН сид** (19). Её плато внутренне согласовано (sd 0.37 % на 2087.2 через 135 000
   шагов), а главный вывод — обёртывание по 3 осям из 3 — топологическая двоичная величина, а не число
   рядом с порогом. Но «2087.2» как число — это одна линия, и движок не воспроизводим побитово.
2. **Тест на перколяцию новый**, и первый результат нового прибора обязан быть самым подозреваемым в
   отчёте. Его защиты: он воспроизводит «не перколирует» на трёх независимых системах, его собственный
   внутренний контроль (заведомо компактное подмножество) не обёртывает ни на одном снимке, и он
   согласуется с двумя независимыми сигналами, написанными не для этого. Но на **специально
   построенном** объекте известной топологии его никто не прогонял.
3. **`cavityVolume` на перколирующей сетке — не лумен.** Это заливка междоузлий внутри собственной
   ограничивающей области объекта. Цитировать «50.5 σ³ против 370.8656» как отставание замкнутости
   поэтому **щедро** к модели, а не сурово: у сетки междоузельная пустота вообще не является
   внутренностью протовезикулы.
4. **Модуль изгиба κ так и не измерен** (ранг A, недоказано): окно подгонки спектра ундуляций
   невалидно, наклон log-log −1.056 против теоретических −4 на 4 оболочках до q_max ≈ 0.18. Разброс κ
   между прогонами был 24.6 ε при среднем 79.07 и не уменьшался с числом прогонов.
5. **Двухвостость и длину хвоста в этой модели нельзя развести составом** — голова здесь И ЕСТЬ
   терминатор цепи. Длина на хвост росла 2.845 → 3.490 ВНУТРИ одного прогона при неизменном составе,
   так что даже одно плечо её не держит. Кто считает, что перколяция вызвана длиной хвоста, а не вторым
   хвостом, имеет право сказать, что эта кампания их не различает.
6. **Между O:C = 4 и O:C = 1 не измерено ничего.** Если компактно-но-крупный режим существует, он в
   этой щели.
7. **Одна несогласованность оставлена в дереве осознанно**: три теста `water-bilayer*` кластеризуют с
   открытой z внутри движка «бульона», который z оборачивает. Её размер ограничен 0.26 % их же
   собственным напечатанным `clusterFraction`, а переключение сдвинуло бы три опубликованные строки
   ворот без измеримой пользы.
8. **Инкапсулированная вода читается на 6 из 15 влажных снимков** — на остальных детектор отказывается
   отвечать. Отказ сам по себе результат, но утверждение о замкнутости опирается на 6 снимков, и это
   более ранние.
9. **Известная нестабильность тестов, доказанно не наша**: `tests/soup-grid-resize.test.ts` и 2 из 3
   тестов `rim-lambda-insitu` падают на неизменном коде (второе доказано через `git stash`);
   `tests/soup-drywet-cycling.test.ts` падает и проходит на идентичных повторах — история его
   событийного отношения 0.7143, 0.4978, 0.7171, 0.6961, 0.5941, 0.7116, то есть разброс 0.43× на
   неизменном коде. Ни одна граница не расширена; лечить это надо увеличением ВЫБОРКИ, а не порога.
10. **Испарение здесь — удаление растворителя, а не термодинамика фазового перехода.** Коэффициент
    концентрирования, который модель реально проходит, — **3.20×** против **1400×** у литературного
    цикла (16.07 % от него по логарифму), а углеродный пул к тому же обогащён **~691×** против самого
    щедрого литературного пруда (~15 мМ декановой кислоты, ACS Earth Space Chem. 2023, PMC9869395).
11. **Электростатики нет вовсе**, соль и pH объявлены непредставимыми и не подделываются
    (`data/soup.json`, `saltPhLimitation`, `represented: false`): окно устойчивости везикул жирных
    кислот (pH ≈ 7–9, сдвиг кажущейся pKa с NaCl) — реальная литература, но выразить её здесь нечем.
12. **Глиняная пластина не участвовала ни в одном опубликованном замере** — все плечи всех кампаний
    шли с `clay: false`. На странице прогона она теперь отдельный переключатель с этой же надписью,
    а не молчаливое умолчание.

## 7. Что нужно менять следующей модели

Сформулировано из этих чисел, а не из общих соображений.

1. **Двухвостый амфифил ПО ПОСТРОЕНИЮ, а не по эмерджентности — подтверждено, и теперь с причиной.**
   Чтобы загнать упаковочный параметр Израелашвили p = v/(a₀·l_c) в полосу ½–1 составом, потребовалось
   O:C = 0.333, а это одновременно поднимает длину на хвост 2.11 → 2.79 → 3.49 и вместе с ней —
   связность органической фазы. Фиксированная двухвостая топология при фиксированно КОРОТКОМ хвосте
   (геометрия Cooke & Deserno, чей устойчивый бислой у проекта уже есть) даёт нужное p, **не** повышая
   число ковалентных соседей на молекулу, а перколирует именно оно. Это изменение молекулы, а не
   константы, и оно самое важное.
2. **Ось разбавления, независимая от химии — НОВОЕ, и это то, что нашла последняя задача.** Порог
   перколяции — функция ρ_org, а ρ_org приколочен высоко потому, что `co_bond` не срабатывает при
   пребиотически честном разбавлении (`data/soup.json`, `startBasis` §5: 0 событий `co_bond` за 150 000
   шагов при обогащении 691×). То есть эта модель не может отделить «достаточно химии» от «выше точки
   гелеобразования». Следующей нужна либо химия, работающая при низком ρ_org (настоящая каталитическая
   скорость, а не коэффициент обогащения), либо **готовые** амфифилы, которые можно свободно разбавлять
   — и второе дешевле.
3. **Регидратация, которая не дробит агрегат — СНЯТО как требование.** В этой кампании она не дробила
   (2238 → 2 куска против 1632 → 22 в решающем прогоне). Аффинная рампа рвёт перколирующую массу по
   слабым связям только когда масса слабо связана; при 48 % двухвостых голов она не рвётся. Требование
   оказалось симптомом пункта 1, а не отдельной нуждой.
4. **Ненулевая растворимость мономера / настоящая CMC — открыто и НЕ проверено.** Эта кампания канал
   обмена не ограничивал, поэтому не проверяла его. Цитировать как снятое нельзя.

**Самый дешёвый следующий замер, полностью специфицированный.** Готовые двухвостые липиды (та же
конструкция `tests/water-bilayer-*`, которая уже держит устойчивый бислой при ρ_W = 0.8), без химии,
без испарения, при четырёх плотностях амфифилов, охватывающих порог перколяции, над которым сидит эта
кампания: ρ_amph = 1.34e−2 (этот прогон), 6.7e−3, 3.3e−3, 1.7e−3 σ⁻³ на боксе 54, с
`tests/percolation-check.test.ts` как показанием и замкнутостью как конечной точкой. Это ровно тот
вопрос, который данная модель никогда не могла задать: существует ли при двухвостой топологии
плотность НИЖЕ точки гелеобразования и ВЫШЕ порога по числу молекул? Порог на боксе 54 — 1004 амфифила
= ρ_amph 6.4e−3 σ⁻³, то есть окно, если оно есть, узкое, и арифметика говорит, что оно между первыми
двумя ступенями.

## 8. Как это перепроверить

```
# таблица ворот целиком (около 4 минут: бислой без растворителя, пропускная способность,
# синтетическая оболочка детектора, спектр ундуляций) -- пишет verify/out/gates.json и report.html
npm run verify

# два входных артефакта, которые npm run verify прочитает, но не может пересчитать сам:
nice -n 15 npx vitest run tests/water-bilayer-area-move.test.ts --no-file-parallelism   # ~200 c

CONTINUOUS_RUN_CHECKPOINTS="<чекпойнты кампании>" \
  CONTINUOUS_RUN_ARTIFACT=verify/out/gates-campaign-trace.json \
  PERC_CHECKPOINTS="<они же + контроли>" PERC_ARTIFACT=verify/out/gates-percolation.json \
  nice -n 15 npx vitest run tests/continuous-run-audit.test.ts tests/percolation-check.test.ts
# off-GPU, по чекпойнтам, уже лежащим на диске: 6.5 с на пять снимков при N = 191 778.
# Кампанию заново прогонять НЕ надо и не следует.
```

Если входного артефакта нет, соответствующие ворота выходят **недоказанными с причиной** — старое
число не подставляется. Это правило живёт в `verify/campaign-gates.ts` и пришпилено тестом в
`tests/gates.test.ts`.

Посмотреть своими глазами: `npm run dev`, страница `viewer/run.html`. Заготовка «малый» — 3938 частиц
(470 органики + 3277 воды при измеренной жидкой плотности 0.8 σ⁻³ + пластина глины 191), измеренная
скорость около **2155 шагов/с**. Заготовка «стандартный» — 25 904 частицы, и в её названии стоит слово
ДОРОГО. Вода по умолчанию не рисуется (её больше всех, она прячет химию и стоит кадров); пластина глины
рисуется плитами, а не шарами, и её можно выключить.
